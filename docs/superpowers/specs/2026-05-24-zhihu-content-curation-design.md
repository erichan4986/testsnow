# 知乎内容精编采纳系统设计

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立知乎内容的智能编辑采纳流水线：动态时效判断、AI 质量评估、深度摘要生成、分级报告呈现。

**Architecture:** 三层漏斗过滤（关键词→时效粗筛→AI质量评估）+ 批次 DeepSeek 分析（5条/批次）生成结构化摘要，入选内容进入报告 Markdown，未入选内容写入 Obsidian 知识沉淀。

**Tech Stack:** Python, DeepSeek API (OpenAI-compatible), JSON structured output

---

## 背景

当前知乎板块仅做简单列表展示（标题+300字截断正文），存在以下问题：
- 无时效判断，一年前的股价预测和最新产业分析混在一起
- 无质量评估，低质内容（如纯情绪、无论据）占据报告篇幅
- 摘要过短，无法呈现作者的推导逻辑
- 点赞数未被利用作为辅助参考

## 需求清单

1. **动态时效判断**：不统一 cutoff，由 AI 根据内容类型判断有效期
2. **质量优先采纳**：不硬性看点赞，AI 评估论据充分度、逻辑清晰度
3. **深度摘要**：≥175字摘要 + 逻辑链条 + AI 独立判断
4. **知识沉淀**：未采纳内容自动进入 Obsidian
5. **成本控制**：批次处理（5条/批次），减少 API 调用次数

---

## 方案设计

### 一、三层过滤漏斗

```
┌─────────────────────────────────────────────────────────────┐
│  L1 采集过滤（关键词匹配 + 统一90天 cutoff）                │
│  → 快速剔除明显无关/过期内容                                │
│  → 知乎API返回20条 → 粗筛后约12-15条                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  L2 质量评估（DeepSeek 批量评分，5条/批次）                 │
│  → 评分维度：论据充分度(40%)、逻辑清晰度(30%)、             │
│    观点独特性(15%)、时效相关性(15%)                         │
│  → 评分<60分的丢弃                                        │
│  → 约12条 → 筛选后约6-8条                                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  L3 时效性判断（DeepSeek 同批次输出有效期）                 │
│  → 内容类型 + 有效期判断                                   │
│  → 当前日期 > valid_until 的丢弃                          │
│  → 约6-8条 → 最终约4-6条进入报告                          │
└─────────────────────────────────────────────────────────────┘
```

**为什么 L1 仍保留统一 cutoff？**
作为粗筛减少 DeepSeek API 调用量。90天能覆盖财报周期（季度），又不至于让批次太大。AI 在 L3 会对内容进行更精确的有效期判断。

### 二、DeepSeek 批量分析 Prompt 设计

**批次输入**：5 条知乎文章的标题 + 正文（截断至1000字/条）

**批次输出**：JSON 数组，每条包含：

```json
{
  "quality_score": 78,
  "content_type": "产业深度分析",
  "valid_until": "2026-08-24",
  "summary": "≥175字的摘要，提炼核心论点...",
  "logic_chain": {
    "premise": "前提假设/背景...",
    "evidence": "论据/数据...",
    "reasoning": "推理过程...",
    "conclusion": "结论..."
  },
  "judgment": "AI对该观点的独立判断（认可/质疑/补充）...",
  "include_in_report": true,
  "reason_if_excluded": ""
}
```

**内容类型枚举**：
- `短期股价预测` → 有效期 14天
- `事件点评` → 有效期 30天
- `财报分析` → 有效期 90天（至下次财报）
- `产业深度分析` → 有效期 180天
- `竞争格局分析` → 有效期 180天
- `宏观政策解读` → 有效期 60天
- `投资策略分享` → 有效期 60天
- `其他` → 有效期 30天

### 三、评分维度细则

| 维度 | 权重 | 说明 |
|------|------|------|
| 论据充分度 | 40% | 是否有数据、案例、引用支撑 |
| 逻辑清晰度 | 30% | 推理链条是否完整、有无跳跃 |
| 观点独特性 | 15% | 是否提供非共识视角 |
| 时效相关性 | 15% | 对当前投资决策的价值 |

### 四、报告呈现格式

入选报告的内容按以下格式渲染（最多展示5条）：

```markdown
## 七、知乎内容精选

> 本次从知乎采集 N 条内容，经 AI 评估筛选出 M 条高质量内容纳入报告。

### 1. [文章标题](链接)
**作者** (认证状态) | 编辑时间 2026-05-20 | 👍 128 | 质量分 78/100 | 有效期至 2026-08-24

**摘要**：
（≥175字，核心论点提炼，不含主观评价）

**逻辑链**：
- **前提**：...
- **论据**：...
- **推理**：...
- **结论**：...

**判断**：
（AI 对该观点的独立点评。可认可、可质疑、可补充。若质疑，需说明理由。）
```

### 五、知识沉淀规则

未入选报告的内容自动写入 Obsidian：
- 质量分<60 的内容
- include_in_report=false 的内容
- 超过 valid_until 的内容

写入位置：`knowledge/10-Stocks/<stock_name>/<date_str>-知乎沉淀.md`

内容包含：标题、作者、URL、质量分、未采纳原因（AI 给出）。

### 六、数据流

```
ZhihuCollector.collect()
    ├── _request() → 知乎API原始数据
    ├── _is_stock_macro_related() → L1 关键词过滤
    ├── ZhihuCurator.curate() → 新增组件
    │   ├── 统一 cutoff 粗筛
    │   ├── DeepSeek 批量质量评估 + 摘要生成
    │   ├── 按 valid_until 过滤
    │   └── 返回 report_items + knowledge_items
    └── 写入 Obsidian（分类写入 知乎相关 + 知乎沉淀）

PerStockReporter.generate_stock_report()
    ├── _zhihu_section() → 读取 report_items
    └── 渲染为 Markdown（摘要+逻辑链+判断）
```

### 七、关键决策记录

1. **批次大小选5条**：平衡 API 成本和 token 长度。5条×1000字=5000字，加上 prompt 约 6000-7000 tokens，远低于 DeepSeek 8K 上限。
2. **L1 cutoff 90天**：覆盖财报周期（季度），同时淘汰明显过期的短期预测。L3 会进一步精确判断。
3. **质量分阈值 60分**：允许一定比例的边缘内容进入报告，避免过度严格导致内容匮乏。可根据实际效果调整。
4. **摘要≥175字**：确保能完整呈现一个论证链条（前提+论据+推理+结论），约3-4个短句。
5. **不硬性过滤点赞数**：点赞受发布时间、作者粉丝量影响，质量分更能反映内容本身价值。点赞仅作为辅助参考展示。
