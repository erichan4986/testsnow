## Findings

No blocking findings after Codex narrow fixes.

The implementation follows the design:

- `KnowledgeSynthesizer.extract_core_facts()` asks for `source_refs`.
- `source_refs` are normalized and capped at 3.
- `fact` / `data` citation markers are stripped.
- `SynthesisSkill` deterministically enriches provenance from existing citations.
- `AgentReach(...)` sources are excluded from supporting provenance.
- `DeepAnalysisRenderer` renders a non-citation-like evidence cell.
- Old-style facts without provenance render as `未绑定引用 (unknown)`.

## Codex Narrow Fixes

Codex found two edge cases during review and fixed them directly:

1. Non-integer numeric refs:
   - Before: `int(2.7)` could accept a float as ref `2`.
   - After: only real ints and digit-only strings are accepted; bools/floats are dropped.

2. Invalid refs after the source-label cap:
   - Before: enrichment could stop scanning after two accepted labels and miss a later invalid ref.
   - After: enrichment scans all refs for validity, while still capping displayed labels at 2.

Added tests:

- `test_enrich_still_marks_partial_when_invalid_ref_after_label_cap`
- `test_enrich_drops_non_integer_refs`
- Strengthened `test_extract_core_facts_drops_invalid_and_duplicate_refs`
- Changed `extract_core_facts` tests to use `client=object()` so they do not depend on local API-key environment.

## Risk Score Drift Review

Runtime validation observed risk score drift:

- Previous comparable report: `4.0/10（中等风险）`
- Current report: `5.5/10（高风险）`

Codex checked the risk path:

- `RiskRenderer` passes `synthesis_text` to `risk_score_section()`.
- `synthesis_text` is generated by `_flatten_synthesis_text()` from the five narrative sections only.
- `core_facts` and provenance fields are not included in `synthesis_text`.
- The provenance implementation does not modify `risk_renderer.py` or `scoring_engine.py`.

The concrete risk-factor delta is:

```text
Current 5.5:
- 技术破位 +1.0
- 流动性差 +1.0
- 竞争格局恶化 +1.5
- 资金流出 +1.0
- 技术路线风险 +1.0

Previous 4.0:
- 技术破位 +1.0
- 流动性差 +1.0
- 资金流出 +1.0
- 技术路线风险 +1.0
```

Root cause:

- The additional `竞争格局恶化 +1.5` is triggered by existing keyword matching in `risk_score_section()`.
- Current LLM narrative contains terms such as `降价周期`, which match the existing qualitative-risk keyword list.
- This is existing stochastic LLM-text sensitivity in the risk model, not provenance pollution.

Follow-up recommendation:

- Treat LLM-keyword risk scoring as a separate quality issue. A future task should make qualitative risk extraction more deterministic or source it from structured risk factors rather than free-form narrative keyword hits.
